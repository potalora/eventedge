# Coverage and runtime repair acceptance

The requested result is a fresh isolated sixteen-book run with complete required source and analysis coverage, within the existing source, model and worker deadlines, followed by immutable replay, independent review and CI. Existing failed and conditional observations remain intact. This work does not authorize merging, deployment or production changes.

## Established defects and implementation sequence

1. **Repeated policy-context validation.** Every signal provenance read/write reloads the database row and repeatedly canonicalizes and hashes the same large validated context. On a WAL-aware copy of a retained 1,194-signal book, context validation consumed 96.4% of profiled provenance-read time. Add a bounded per-ledger cache of successful validation facts keyed by the entire freshly read raw row. Keep fresh SQL reads and fresh decoded return objects. Test same-connection and external mutation, rollback, deletion/reinsertion, identity and digest tampering, mutable return isolation, eviction and oversized rows. Compare logical ledger/replay output and profile the identical copied workload. This is an optimization, not permission to trust a stale database row.
2. **Acceptance oracle.** The old scratch evaluators can report success with missing cohorts, absent staging fields, unavailable reports or a timed-out child exiting zero. Prepare a new fresh-run harness and supervisor with exact cohort/status requirements, durable evidence checks, bounded diagnostics, native scoped transport observation and closed-process verification. Exercise negative cases offline before any fresh run. Preserve existing harnesses and archives as historical evidence.
3. **Filing text and entity coverage.** The retained source bundle contains 2,894 distinct qualifying accessions; 30 have hydrated text and 2,864 are still admitted with exhausted text budgets. Current index-plus-document requests exceed the 300-second acquisition deadline at the SEC rate limit even before discovery and prior filings. Investigate supported complete-submission and daily archive acquisition with bounded probes before choosing an implementation. Preserve the complete declared accession population. Retain precise safe semantic-failure diagnostics through frozen window coverage so a partial HTTP-200 search can be explained without relaxing completeness checks. Separately reproduce and repair inline-XBRL contamination, form-specific evidence extraction/dispatch and lost role-bound issuer identity. Schema-valid neutral output is not evidence that a document was adequately analyzed.
4. **Remaining runtime.** Measure supported installed OpenBB bulk behavior for the complete enrichment population. Investigate bounded candidate concurrency only with independent analyzer state, inherited deadline/context, deterministic ordering, independently validated exact-response reuse and complete failure accounting. Neither a narrower enrichment population nor a completed analysis prefix is an acceptable speed optimization.
5. **Fresh verification.** After fixes and offline regressions, review the exact candidate and harness, freeze code/config/session identity, run on a new empty scratch generation using native current sources and models, retain private requests/responses and complete populations, and independently check all sixteen books and 48 strategy-health records. Require native committees for naturally eligible books, complete staging/accounting, reporting and process closure. Replay the same closed state with zero acquisitions and exact logical database/input invariance. Finish with independent review and CI for the final commit, updating the existing topic PR without merging.

## Fixed acceptance boundaries

- Source acquisition retains its 300-second deadline. All horizon analyses and committee calls retain one shared 2,400-second deadline and a 120-second individual model limit. The worker remains bounded at 3,600 seconds and the scratch main supervisor at 3,500 seconds, including startup/reporting/closure rather than subtracting pauses. Replay has its separate existing 120-second supervisor; report both timings explicitly.
- Exact expected cohort set: four horizons (`30d`, `3m`, `6m`, `1y`) times four sizes (`5k`, `10k`, `50k`, `100k`). Every book must have valid input coverage, execution and staging, a nondegraded durable committee outcome, complete model coverage and no unresolved input quarantine. Empty valid committees and genuine no-event scopes are allowed; fabricated inputs or forced trades are not.
- Exact health population: twelve strategies times four horizons, including only the four already policy-disabled records. Every enabled required source/analysis contract must be satisfied. Discovered, admitted, excluded, hydrated, required, validated and failed populations must reconcile before filtering.
- No relaxed provider-completeness checks, relabeled missing evidence, post-failure exclusions, deadline resets, favorable historical session selection or retained fixture injection. A supported source-neutral/no-listed-target assessment needs its own explicit validated evidence; `direction=neutral` alone does not establish completeness.
- Preserve production code/state/service identity and all earlier evidence. Fresh scratch state contains no preseeded financial, source, reference, volatility or model observations. Reports and replay must preserve all seventeen financial SQLite databases logically and immutable input files byte-for-byte.

Bulk transfer throughput, substantive document extraction and full model throughput remain unproven. If bounded measurement establishes that the unchanged full contract is infeasible, retain the measured failure and present the exact policy/resource decision required. Do not report the goal achieved from component tests or the earlier conditional runs.
