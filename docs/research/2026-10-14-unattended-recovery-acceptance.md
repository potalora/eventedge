The source drill separately completed four isolated synthetic generation profiles: enabled, CFTC retired, EDGAR retired and reenabled. Each completed and replayed all 16 books. Retired providers received no fixture transport calls; reenabled providers resumed acquisition. Accepted inputs and earlier profiles remained unchanged. The retained drill identifies its pre-commit source hashes; current PR checks and the private acceptance index provide final exact-commit CI and Linux packaging outcomes.

Source retirement requires `source_lifecycle_policy=explicit_retirement_v1`, the prospective decision clock and dependency isolation. `retired_sources` names each source, a reviewable reason and its exact dependent strategy list; `disabled_strategies` must explicitly disable those strategies with the same reason. No source is retired automatically. The accepted bundle freezes the effective dependency map and digest, and each affected horizon retains a zero-signal policy exclusion that reporting validates.

EDGAR's closure includes its filing strategies and the legacy litigation/regulatory identity helpers. Nonempty court, regulation and government-award fixtures verify that excluded consumers never screen, unresolved award identities remain journal-only and no SEC lookup occurs. An unforeseen empty-ticker fallback refuses a retired identity dependency before model or provider access. Shared regime/enrichment sources and conflicting source-evidence policies are rejected. Existing acquisition-only filing exclusion and historical `data_sources` semantics remain intact. Retirement and reenabling belong to reviewed new generation configurations.

Generation creation records a durable intent before worktree/state effects. Retrying resumes the original identity rather than reusing historical state or following a changed HEAD. Retirement publishes the retired status before optional code cleanup; a cleanup retry must also successfully sync the manifest directory after a prior sync failure. Unknown data, modified checkouts, conflicting profiles and ambiguous Git pointers require review; the lifecycle does not reset them automatically. Process-interruption tests do not establish power-loss durability of Git internals.

Runtime recovery validates all 16 bound execution contexts before accounting effects. It resumes committed phases from accepted inputs and can finish staging only from frozen screening, prices, volatility, enrichment and committee decisions before the next eligible open. It cannot fetch missing inputs, rerun models, reopen invalid accounting or reconstruct a missed historical sample. Mixed book identities, corruption, unresolved authentication and exhausted attempts require user action. Ordinary accepted source failures or missed staging preserve the sample and wait for the next session.

The controller journals bounded attempts and verifies frozen profile bytes, the exact generation checkout and Git identity. Older accounting recovery precedes a new daily sample. A canonical exclusive lease pins the active roster throughout the existing daily wrapper, including its preflights and reports. Process-group cleanup and service resource limits bound interrupted work. A fresh status heartbeat exposes recovery, waiting and required-action states through the existing observer.

Recovery has a distinct completion receipt. Reporting recomputes its source, committee, phase, staging, economic and metric proofs before accepting recovered accounting/staging. Original failed or missing daily output, manifest history and preflight incidents remain visible and unchanged; no original success wire is fabricated. Receipt, source, frozen-profile, committee and cash-event mutations fail verification. New complete accepted evidence can resolve an older preflight authentication incident without erasing that provenance.

The runtime fixture uses actual abrupt child-process exit after a committed accounting phase, then a fresh process reopens the 16 books and checks repeated recovery for duplicate effects. Its four accelerated XNYS sessions are October 14, 15, 16 and 19: an interrupted normal launch, a missed sample, an accepted provider failure and subsequent ordinary sessions. Clock acceleration is not a wall-clock multi-day endurance test. Provider/model responses remain synthetic; native process tests do not establish provider or production behavior.
