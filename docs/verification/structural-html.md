# Structural HTML deferral

`verified_supported_documents_v3` is a separate prospective filing policy. Pedro approved its finite structural proof boundary and the HTML-only raw selected-body ceiling of 24 MiB on October 11, 2026. V1/v2 policy identities and historical failed runs retain their original meaning. Nothing in a parser diagnostic establishes fresh acquisition, native execution, immutable replay, supported analysis, order authority or deployment.

## Exact proof boundary

The `sec-html-structural-v2` verifier consumes the whole strict UTF-8 selected HTML body without parser recovery. Every byte belongs to a contiguous token span bound to the original body SHA256 and its own SHA256. Complete tokens, decoded attributes and CSS declarations are retained. Repeated hashes and attribute/CSS records are interned; compact token arrays preserve every occurrence, span and reference. `iter_html_structural_tokens` expands one dictionary view at a time for downstream deterministic checks. Interning changes storage representation, not coverage or resource accounting. The [finite v2 expansion](structural-html-finite-expansion.md) specifies SEC XML/XHTML namespaces, explicit empty tokens, presentation obligations and ordered CSS declarations.

The finite grammar supports ordinary document/container/text elements, explicit table structure, redline tags, declared presentation attributes and finite namespace-bound SEC Inline XBRL families. It validates nesting/content rules, bounded table spans, unique HTML attributes, declarations, comments and terminated known entities. The only ordinary HTML omitted end-tag rule closes an empty or ASCII-whitespace-only paragraph before a specified block start or its parent close; the token records this implicit close. XML-declared XHTML requires explicit closure. Populated paragraphs, EOF-open paragraphs and table omissions fail. Unknown tags/attributes/namespace elements, general namespace rebinding, active content, forms, frames, stylesheets, SVG/MathML, conditional comments, malformed/truncated syntax and unsafe references fail.

Inline CSS uses a finite property/value grammar with bounded numeric declarations, colors, fonts, lengths, shorthand borders/margins, recognized layout/visibility keywords and an explicit optional `!important` suffix. Every accepted declaration stays in the receipt, including repeated properties in exact source order and complete signed numeric padding values a browser might ignore. Legacy unitless numeric source declarations are retained without asserting their browser interpretation. Unknown properties/values, escapes, comments, functions outside the finite numeric `rgb()`/`translate()` grammars, URLs, at-rules and custom properties fail. `css_property_semantics="unverified"` explicitly accompanies the absence of CSS cascade, computed layout, visibility, font availability/glyph coverage or visual meaning proof. Hidden/collapsed declarations do not exclude source spans or erase other duties: the entire selected unit is deferred.

Every `img[src]` occurrence is inventoried independently of navigational anchors, including image-only bodies and repeated image edges. Only safe exact filenames resolving uniquely to same-original native `GRAPHIC` documents are supported. Each target binds its type, sequence, exact original byte range and raw SHA256. External/data/CSS URLs, `srcset`, missing, duplicate/ambiguous, wrong-type or oversized resources fail. Each unique target is decoded once, sequentially, under the inherited callback. The supported SEC UU framing binds the exact begin filename/end delimiter, nonempty declared image payload, decoded length/hash, trimmed zero sextets and ignored sextets only beyond each declared decoded byte count.

This HTML image boundary verifies transport and inventory only. Declared JPEG/PNG/GIF payload validity, JPEG marker/entropy framing, decoded pixels and OCR are **unverified**. This is narrower than the optional JPEG-marker extension in the original design; no successful UU parse is called image validation. An exact image edge creates a visual obligation without inferring its meaning or immateriality.

## Use and bounds

A positive complete table/redline/CSS/image/font/presentation/Inline-XBRL obligation produces `representation="structural_html"`, `native_text_complete=false`, `visual_meaning="unresolved"` and `order_authority=false`. The structural unit contains a source-only projection of every hash-bound text token, including hidden text. Inline tag boundaries add no artificial spaces, preserving split-word continuations; explicit block boundaries separate source words. This projection exists solely for deterministic ownership-incorporation locator scanning. Nonvisual HTML and earlier policies retain their existing visible-text semantics. Its exact UTF-8 hash/byte count/character count are bound in the receipt with `source_text_use="incorporation_locator_only_not_analysis"`; it cannot establish extraction quality or analysis completeness, enter model prompts or authorize orders. All raw `a[href]` declarations remain in the complete token inventory, including explicit XML empty anchors. Native ownership XML, complete native EX-* selection and incorporated-document acquisition obligations remain independent duties and take precedence over deferral.

Only v3 selected `.htm`/`.html` bodies receive the approved 24 MiB raw allowance. PDF, XML, text and each encoded/decoded GRAPHIC remain at 16 MiB. Complete serialized HTML receipts plus selected UTF-8 projections share the unchanged 32 MiB result/provenance bound. Every unique resource's decoded work is reported; resources are processed sequentially and decoded payloads are not retained collectively or rasterized. The 512 MiB original bound, existing parser processes, original inherited deadlines, watchdogs, acquisition/storage bounds and model budgets remain unchanged.

V3 is selected before parsing; technical errors never select a deferral route. Evidence, local source proofs, verifier versions and bounds bind the policy. The parent validates exact receipt schemas, coverage, selected-unit/projection/resource bindings and exact visual reasons. Raw audit independently regenerates the complete receipt from retained originals and rejects resealed alterations. Another selected unit's error, missing acquisition, unresolved ownership duty, parser/deadline/truncation/budget failure or an insufficient model result remains a failure. Complete structural proof alone cannot grant semantic analysis admission.
