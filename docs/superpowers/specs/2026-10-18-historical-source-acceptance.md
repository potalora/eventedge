# Historical source acceptance and reliability learning

Pedro requires real historical data in the test workflow and a retained lesson
for every novel observed source failure. Repair the defects found by the native
and offline campaigns, preserving their original failed results.

Every candidate runs a network-denied replay of recorded source data. Public CI
uses redistributable historical extracts with exact hashes and provenance. Full
supported-source acceptance additionally requires the private retained corpus;
missing evidence fails that gate. Licensed captures, frozen contact/profile
material, credentials and trading state remain outside Git. The two scopes are
reported separately. Synthetic faults remain useful negative controls, but are
never represented as historical observations or the only source acceptance.

Each fixture declares its original format and tested boundary. Original HTTP
bytes test the adapter contract; normalized accepted inputs test downstream
consumers. Reconstructed responses cannot establish a wire contract. Acquisition
time, observation/reference date and data vintage remain distinct. Historical
replay does not establish availability at an earlier decision time, current
source health, model accuracy, financial returns or elapsed continuity.

Source reliability is a bounded report projection plus a reviewed catalog, with
no new service, persistent runtime database or provider calls. Preserve stable
observation identity and pattern novelty. Code defects, configuration/access,
source-or-network, confirmed upstream, harness and unresolved classifications
remain separate. A familiar error pattern cannot establish the current cause.
Only exact reviewed observation evidence can attribute the current failure.
Retries, duplicated diagnostics and replay do not create new empirical failures.

The observed NOAA Access JSON failure remains degraded. Successful static NOAA
data is useful historical evidence, not a substitute for the required Access JSON
contract. Endpoint failures from one host do not establish a provider-wide outage.

Changes land in the existing approved stabilization PR. Do not merge or deploy,
alter source budgets or coverage, reset incidents, replace accepted inputs, or
modify production state. Behavior changes retain the new-generation requirement.
