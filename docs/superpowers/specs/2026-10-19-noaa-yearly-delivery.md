# Explicit NOAA yearly GHCNd delivery

The user approved replacing the failing NOAA query-service acquisition path with official daily-updated GHCNd yearly files after a real full-roster feasibility check. This is an intended acquisition and numeric-policy change for a new generation, not a claim that the Access API is repaired or that its undocumented rounding is reproduced.

Add a separate `NOAAYearlySource` selected only by `autoresearch.noaa_delivery_policy: ghcnd_yearly_v1`. An absent policy retains the existing adapter; any other supplied value fails validation. This keeps the implementation portable to main and the prospective sixteen-book profile without changing existing frozen generations. The stabilization profile will explicitly select the new policy in its existing PR. No runtime fallback, alternate provider, model calls, credential discovery, production writes or deployment are part of this change.

The source must preserve the candidate's ten agricultural states, all eligible inventory-selected station identities, arithmetic state/day/type means, unique regional event-day counts, contiguous requested window, at most seven days of lag, and 180-second absolute acquisition/decode/aggregation deadline narrowed by any parent. Actual acquisition vintage remains separate from the requested observation/reference date. Do not reconstruct earlier information sets from a newly downloaded mutable archive.

Retrieve official station and element inventories and every yearly gzip CSV intersecting the requested window, including December/January boundaries. Use the existing provider request limiter and original deadline. Bound HTTP bytes, decompressed bytes, individual rows, selected records, stations and years; check budgets throughout reads, decoding, parsing and aggregation. Close responses and temporary storage on every path. Complete gzip integrity and EOF validation must precede success. No partial or stale file can establish healthy coverage. Reject malformed selected observations, duplicate station/date/type identities and inconsistent catalogs. Quality exclusions count only the requested observation scope; nonblank quality flags are excluded, trace measurement flags are retained, and missing observations never become zero.

Publish explicit unit policy `ghcnd_metric_exact_to_standard_v1`: Fahrenheit = raw temperature * 9 / 50 + 32; inches = raw precipitation / 254. Preserve existing final summary rounding. Do not claim exact Access JSON rounding parity. Retain public provenance hashes, bytes, actual acquisition times, station-selection identity, dates, quality exclusions and scope without raw payload or arbitrary URL/error leakage. Any failure withholds actionable weather metrics and keeps structured reason/status evidence.

Tests must use exact retained NOAA records with provenance and independent raw `.dly` value checks where available. Constructed corruption cases must identify their real parent input. Positive tests cover real ten-state coverage, conversion, trace/quality flags, cross-year acquisition and full-body checks; negative tests cover incomplete coverage, malformed/duplicate/missing records, truncation, gzip bombs/caps, expired/shorter budgets and resource cleanup. Missing original full files must fail the optional full-corpus acceptance command, never skip or substitute synthetic data.

Acceptance includes focused tests, independent review, offline replay of the complete retained current-year file through the final adapter, a bounded real source-only acquisition through the final selected registry path, candidate profile/configuration binding checks, and appropriate complete CI on pushed topic branches. Original failures and their immutable evidence remain retained. No five-session continuity, full financial native workflow or production activation is implied.
