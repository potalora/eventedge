# Real-source and live-model workflow acceptance

The acceptance tool must run the pinned candidate's complete paper workflow in a
fresh disposable generation with actual source acquisition and actual configured
model calls. Endpoint probes followed by generated workflow inputs do not qualify.
The user explicitly selected real sources and live models on October 31, 2026.

The tool lives on a topic based on main and accepts a separate exact candidate.
It clones that candidate locally without hardlinks, removes remotes, retains the
candidate commit, freezes the supplied stabilization profile with only disposable
path substitutions, and uses the real generation manager. Its real-clock guarded
prospective launch processes the latest completed session before the next open.
An ordinary idle controller tick remains a separate assertion. No source policy,
model, effort, risk setting, execution flag or existing deadline is relaxed.

All application state, ledgers, caches, captures and reports belong to the private
test root. Native authentication uses the existing adapter's canonical shared
parent-directory lock and atomic refresh; it is never copied into a second lock
domain. Normal credential refresh is allowed, but secrets cannot enter tapes,
logs, profiles or Git. Supply only enabled source credentials. Broker writes and
real notifications are forbidden. Root reviews the complete execution boundary
before the first native run.

Transparent hooks record actual source responses and model text without replacing
native transport or eagerly reading streamed bodies. A private tape identifies
candidate, profile, dependencies, phase, operation, canonical public request and
atomic duplicate occurrence. HTTP decoded bodies, SDK return values and normalized
accepted envelopes have distinct provenance. Failed and incomplete observations
remain failures. Model recording preserves response observers, provenance and
deadline checks. Replay requires exact request binding and denies missing or extra
requests; no generic answer or live fallback is allowed.

Acceptance distinguishes workflow completion, source completeness, model-role
coverage and continuity. Natural empty data, abstention and zero trades are valid;
they cannot establish branches that did not execute. Independently check sixteen
books, accounting/staging, canonical report reproduction, producer observations
and native consumption with fake delivery. The initial native run is followed by
network-denied accepted-state replay. Cold acquisition replay is supported only
for actually recorded boundaries, with explicit gaps otherwise.

Controlled edge cases retain immutable parent captures: source denial/throttle/
timeout, malformed or partial data, duplicate/missing symbols, invalid pagination,
stale/future dates, model timeout/refusal/malformed output, wrong identities,
interruption, duplicate execution and calendar/startup boundaries. Changed model
requests cannot reuse unrelated recorded responses. Classify native observations,
replay and controlled mutations separately. A single session proves neither future
availability, subsequent fills nor five-session qualification.
